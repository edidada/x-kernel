# ktime_types - 安全与可靠性分析

## 信任模型

`ktime_types` 信任调用者只在真实的 ABI、硬件、协议或序列化边界使用整数转换 API。
类型本身负责规范化表示，并阻止不同时钟域直接运算。

## 外部边界 / 攻击面

该 crate 不访问用户内存、设备、网络或文件系统。外部输入只会通过构造函数进入；
调用边界应先验证秒、纳秒范围及有符号性。

## 内存安全不变量

无 `unsafe` 代码。所有类型由普通 Rust 值组成。

## 线程安全

类型不含内部可变状态，可在线程和 CPU 之间复制。时钟源的同步由提供这些值的子系统负责。

## 威胁分析

| 编号 | 威胁描述 | 影响等级 | 触发条件 | 应对措施 |
|------|----------|----------|----------|----------|
| T-01 | 不同时钟域被当作同一时间轴 | 中 | 使用裸整数绕过类型 | 内部 API 使用 `Instant<C>`；整数转换限制在边界 |
| T-02 | 外部时间值溢出 | 中 | 未验证的超大 duration 或 timestamp | 提供 checked/saturating API，边界拒绝或钳位输入 |
| T-03 | 墙钟回拨被当作正 duration | 中 | realtime 时间排序反转 | `SystemTime::duration_since` 返回错误而非下溢 |

## 已知限制

`TimeSpan` 只能表达非负时长；需要带符号差值的协议必须在协议边界单独建模。

## 形式化验证边界

`verification/harnesses/mod.rs` 对 `TimestampLimits::truncate` 建立性质检查；
`verification/harnesses/span.rs` 覆盖 `TimeSpan` 的显式数值 API。
证明通过独立 crate 的路径依赖调用生产库，业务 src 不声明验证模块。
输入前提只接受有效的范围、粒度和规范化时间值；构造器对非法配置的预期
panic 不属于无 panic 性质的适用范围。输入可达性检查覆盖上下界、内部、
退化范围、极端秒数和粒度端点，防止这些输入类别被前提排除。

`TimeSpan` 验证覆盖有效时长的完整秒/纳秒范围，以及完整 `u64` 单位输入
和 `u128` 总纳秒输入。checked 运算同时检查成功值与拒绝条件，
saturating 运算检查钳位边界；可达性检查覆盖进位、借位和临界溢出。
`new` 的正常返回性质仅适用于总时长可表示的输入。
同时保留 9 个具体边界的 `should_panic` 见证；它们自身不证明所有非法输入必然 panic。

`Instant` 的正常返回性质分别实例化到四个公有时钟域，检查时钟原点下溢、
最大时长上溢、时间差方向和饱和行为。跨时钟域的比较和相减用编译失败示例检查。
`SystemTime` 检查完整 `i128` 构造输入的接受范围、负数向下规范化、
进位借位、跨 epoch 运算及 `duration_since` 成功/错误的精确幅度。
早期运算符溢出及 `TimestampLimits` 非法构造的 panic 入口是具体边界见证；
后续的全域契约采用下面的额外审计。

新增的 `panic_contracts` 验证为全域检查：输入域必须可达，正常返回必须
不可达，而且报告中的失败只能来自列明的 panic 位置。
运行脚本锁定 Kani 报告版本，并为每次运行创建独立目录，避免接受旧报告。
报告解析器对缺失、未知状态及非预期失败拒绝通过；其负向测试与源码故障
注入检查了“部分非法输入不 panic，但 should_panic 仍成功”的反例。
这些构造/运算路径有限且不关闭安全或展开检查；不将此方法推广到任意循环程序。
clamp 检查完整合法区间的钳位结果和逆序区间的必然 panic；报告审计严格限定
所列类型的 `Ord::clamp` 边界断言，不能以其他失败替代所需 panic。

Hash 验证记录字段写入的类型、值和顺序，没有使用可能碰撞的哈希摘要。
这不保证具体哈希算法无碰撞，也不承诺跨 Rust 工具链版本的 Hash 格式稳定。
Debug 检查五类值的默认格式化输出非空且长度有界，并对任意字节容量的写入器
检查首次拒绝后不再写入、返回错误当且仅当发生拒绝。保留四个立即拒绝入口。
内部循环使用展开上限 16 或 32，并为固定版本 core 的字符计数循环指定更小的
独立界；所有展开断言保持开启。界过小必须验证失败，不能跳过超界路径。
这些性质不保证输出文本正确；确切字节串及所有格式选项仍只有回归测试。

证明结论依赖 Kani、配套 Rust 编译器、CBMC 和求解器的正确性，
不等同于整个 crate 或最终内核机器码的正确性证明。
未覆盖时间源、并发调用者、完整格式化文本、具体 Hasher 的内部算法和最终机器码。
自定义 marker 已有代表性实例和无 marker trait 约束的泛型编译示例，
但 Kani 的单态化证明不等于对所有 Rust 类型的全称证明。
详细规格与运行记录见 [contracts.md](../verification/contracts.md)。
验收清单固定已审查的生产指纹与证明入口；完整验收拒绝漏跑及普通 cover 不可达，
并核对求解前后的输入哈希。清单防止无意沿用旧结论，不替代规格审查或抵御恶意
修改验证工具链。保留缺口与维护流程见 [验证说明](../verification/README.md)。

## 审计清单

- 新 API 是否返回语义类型而不是带单位的整数。
- `Instant` 运算双方是否属于同一时钟域。
- 原始整数转换是否紧邻 ABI、硬件、序列化或第三方接口边界。
- 使用饱和转换的边界是否明确接受 `u64::MAX` 作为不可表示值的钳位结果。
