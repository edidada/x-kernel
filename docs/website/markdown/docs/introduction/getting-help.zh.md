# 获取帮助

使用 [X-kernel 社区](https://x-kernel.zulipchat.com)交流使用方法与设计问题。在 [Gitee Issues](https://gitee.com/openkylin/x-kernel/issues)报告能够复现的缺陷，或提出可以明确描述的改进建议。

## 提问前

1. 查看[快速开始](quick-start.zh.md)，确认平台配置和执行顺序。
2. 搜索已有 Issue 与社区讨论，检查是否已有相同现象。
3. 缩小复现步骤，记录首次出错的命令。末尾的 `make` 错误可能只是上游失败的结果。

## 提供可复现的信息

请包含主机系统、仓库提交、平台配置、工具链版本、rootfs 来源和完整复现步骤。可以先收集：

```bash
git rev-parse HEAD
git status --short
rustc --version
qemu-system-aarch64 --version
```

使用其他架构时，替换 QEMU 命令。说明采用哪个 defconfig，以及之后通过 menuconfig 或手工修改了哪些选项。

在 Bash 中记录构建日志，同时保留构建失败的退出状态：

```bash
set -o pipefail
make build 2>&1 | tee build.log
```

对于启动问题，也请提供从启动开始到故障位置的串口日志，而不只是一张最终错误截图。分享前检查日志中的本机路径、凭据和其他私人信息。

## Issue 模板

```text
问题概述：
预期行为：
实际行为：
仓库提交：
主机系统 / CPU 架构：
平台 defconfig 与额外修改：
Rust / QEMU / 交叉编译器版本：
rootfs 来源：
复现命令：
首个错误与完整日志：
是否修改过源码：
```

功能建议请说明使用场景、当前限制和期望行为。暂时没有复现步骤的问题可以先在社区讨论；不需要为了提问先弄懂整个内核。

## 安全问题

如果问题可能涉及可利用的漏洞或敏感信息，请先查阅仓库最新的安全披露说明；没有说明时，联系维护者确认私密沟通渠道，再分享敏感细节。本文不提供未经项目确认的安全邮箱或响应时限。

## 参与项目

阅读仓库当前的贡献说明和编码约定，将问题描述与相关源码联系起来。提交改动时说明动机、验证方式和影响范围。组件内部设计与接口细节以相应 crate 中的文档为准。
