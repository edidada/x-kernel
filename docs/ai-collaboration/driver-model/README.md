### Q12/Q13 源码核对

用户在看到下列调查结论及范围解释后答复“好 同意”；该确认覆盖 Q12/Q13 的解释，
并同意汇总完整需求供审阅，不视为事先批准尚未展示的 v0.2 全文。

本轮为静态调用链核对，不是运行验收；以下是 agent 事实调查及范围推导，不扩大用户批准范围。

- Linux 普通 probe/remove、解绑和注销路径使用可睡眠的任务上下文；设备锁为 mutex（`/root/linux-stable/include/linux/device.h:1102`），probe 要求设备锁（`/root/linux-stable/drivers/base/dd.c:878`），解绑持锁执行 remove（同文件 `:1314`）。不能从禁止睡眠的上下文直接执行这些流程，亦不能据此声称所有驱动 API 都可睡眠。
- 允许回调睡眠不意味着允许生命周期重入；Linux 明确指出 remove 内再次解绑同一设备会死锁（`/root/linux-stable/drivers/base/dd.c:1388`）。需求须覆盖序列化、锁序和等待约束，具体 Rust 同步机制尚未选定。最终对象 release 与 remove 的上下文也不能混同。
- sysfs/uevent 已有真实启动集成：`core/kruntime/src/lib.rs:310`、`fs/boot/src/lib.rs:54` 初始化投影和事件发布，`fs/boot/src/lib.rs:321` 挂载 sysfs；`drivers/integration/kdevice-uevent/src/lib.rs:111` 和 `:286` 接入节点生命周期并发送 netlink 事件。因此不能将它们整体列为非目标；迁移须保留已有行为，不要求补齐 Linux 全套 ABI。实际设备节点事件不等于物理热插拔发现。
- 驱动 suspend/resume 当前仅有默认回调，未发现覆盖实现或调用链（`drivers/contracts/kdevice/src/driver/mod.rs:304`）；系统挂起仍有设备静默 TODO（`core/ksyscall/src/sys.rs:217`），平台挂起返回不支持。未发现设备 runtime PM 的完整使用链。现存 ARM timer 恢复修正不等于驱动 PM 编排，不得在迁移时误删。
- 物理热插拔发现未找到接通路径；当前是启动枚举/probe（`drivers/integration/kdriver/src/manager.rs:47`），rescan 接口未发现外部调用（同文件 `:85`）。本阶段保留未来事件接入空间，不实现硬件插拔发现；解绑/注销仍按 Q5 验收。
- 动态模块装卸未发现支持；配置生成器明确将 tristate `m` 视为 `y`（`xtask/xconfig/src/config/generator.rs:18`），驱动按编译配置注册。按 Q13 本阶段不实现可装载模块；模块卸载与设备解绑不是同一能力。
