# R1 票据与旧前置要求对照

用户询问九张 ticket 是否包含此前前置功能要求后，逐项核对旧 P1—P7 及旧
ticket-plan 的具体验收。九票范围包含主要能力，但初次落票时 P3 及下游
所有权的验收过于笼统；已补充到原有票，不新增需求、不改编号和依赖图。

| 旧前置 | 当前落点 | 状态与边界 |
|---|---|---|
| P1 可靠同步等待 | 已合入 Completion + R1-03 | 原语不重做；可靠排空合同、host 接线及通知/错误测试尚需完成 |
| P2 IRQ 同步释放 | G-IRQ + R1-07/08 | 旧验收 worktree 仍待复核/review/交付；驱动接入及共享 action 隔离仍需验证 |
| P3 固件/平台 DMA 事实 | R1-08 | 已补充真实来源、缺失属性、多段范围、区间溢出和不可表示配置；先于真实资源验收 |
| P4 新 OS 能力宿主实现/安装 | R1-01（管理）、R1-03（等待）、R1-08（真实资源） | 实际 provider 先于 probe 安装；MMIO/IRQ/DMA 取得、部分失败和释放配对均需验证 |
| P5 VirtIO 实例 DMA 后端 | R1-06 | 独立库交付；ring/request/indirect 同实例，静态 Hal 兼容及可复现依赖 |
| P6 停机与 outstanding 回收 | R1-07 | 依赖 R1-06/G-IRQ；停止确认后回收、无伪造熵、无双重映射解除 |
| P7 枚举与启动装配 | R1-08 | 旧注册前唯一分流，空槽忽略；非 RNG 路径保留；真实 MMIO 证明 |

另有不属于 P1—P7、但不能因重排票而丢失的旧验收：

- 旧下游所有权票 → R1-01：测试控制器/孩子、父服务保活、非本次拥有设备
  不误删、枚举提交与退出交错。已补明确复选项，不只写一句“总线负责”。
- 旧延后探测票 → R1-02：依赖通知窗口、pump 退出窗口、注销后迟到工作。
- 旧整体兼容验收 → R1-08/09：双实例、反复生命周期、节点/事件、未迁移
  VirtIO 路径；每票本身仍需测试，不全部推迟到最终验收。

本轮是原需求到验收项的补全，不把已批准设计改成增加能力的新版。实际
执行若 R1-01 或 R1-08 超出单票可审查规模，应先按可演示行为调整切片并
确认，不以九票总数为由省略这些要求。这里“已落票”不等于已实现。
