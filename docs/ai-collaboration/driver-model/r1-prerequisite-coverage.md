# R1 票据与旧前置要求对照

用户询问九张 ticket 是否包含此前前置功能要求后，逐项核对旧 P1—P7 及旧
ticket-plan 的具体验收。九票范围包含主要能力，但初次落票时 P3 及下游
所有权的验收过于笼统；已补充到原有票，不新增需求、不改编号和依赖图。

| 旧前置 | 当前落点 | 状态与边界 |
|---|---|---|
| P1 可靠同步等待 | 已合入 Completion + R1-03 | 本分支已验收：可靠排空合同、host 接线及通知/错误测试；原语不重做 |
| P2 IRQ 同步释放 | G-IRQ + R1-07/08 | `00b4f0fc0` 已交付 NativeIrq 和具体 RNG 的 SMP 尾部、共享 peer 及负控；不再依赖旧未提交 worktree，不声称物理 IRQ/MSI 排序证明 |
| P3 固件/平台 DMA 事实 | R1-08 | 已验收真实来源及异常输入；限定 QEMU coherent identity 窗口，不推广为 IOMMU、非一致性或 above-4-GiB 实测 |
| P4 新 OS 能力宿主实现/安装 | R1-01（管理）、R1-03（等待）、R1-08（真实资源） | 已验收 probe 前安装、Native MMIO/IRQ/DMA 取得、部分失败回滚及配对释放 |
| P5 VirtIO 实例 DMA 后端 | R1-06 | 已交付 checked-in vendor；ring/request/indirect 同实例，静态 Hal 兼容及可复现依赖；未在本轮重复执行不变源码的独立库测试 |
| P6 停机与 outstanding 回收 | R1-07 | 已验收 reset 确认后同步排空及回收、取消不产熵、无双重 unmap；正常完成尾部与 pending 取消分别取证 |
| P7 枚举与启动装配 | R1-08 | 已验收旧注册前唯一分流、空槽忽略、真实 MMIO 生命周期及旧 PCI 兼容；不等于物理热插拔 |

当前状态更新于 2026-11-04，证据、复跑命令及明确非声明见
[R1-07/08 收口](r1-07-08-closeout-2026-11-04.md)。这里只关闭批准范围的
前置交付，不代替 R1-09 整体验收，也不关闭新交接的网络生命周期任务。

另有不属于 P1—P7、但不能因重排票而丢失的旧验收：

- 旧下游所有权票 → R1-01：测试控制器/孩子、父服务保活、非本次拥有设备
  不误删、枚举提交与退出交错。已补明确复选项，不只写一句“总线负责”。
- 旧延后探测票 → R1-02：依赖通知窗口、pump 退出窗口、注销后迟到工作。
- 旧整体兼容验收 → R1-08/09：双实例、反复生命周期、节点/事件、未迁移
  VirtIO 路径；每票本身仍需测试，不全部推迟到最终验收。

本轮是原需求到验收项的补全，不把已批准设计改成增加能力的新版。实际
执行若 R1-01 或 R1-08 超出单票可审查规模，应先按可演示行为调整切片并
确认，不以九票总数为由省略这些要求。这里“已落票”不等于已实现。
