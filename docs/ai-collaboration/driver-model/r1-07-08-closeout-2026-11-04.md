## Current-run evidence

Local directory:
`.scratch/driver-model-r1/evidence/r1-07-08-closeout-2026-11-04/`.
Runs are serial, use the worktree-private regular `disk.img`, disable network
and vsock, and do not request a performance-exclusive window. Each terminal
fixture has its own fresh guest; it is never mixed into a broad suite.

Configuration starts from `platforms/kplat-aarch64/qemu_defconfig` and
`make defconfig`. For destructive fixtures select `KFEAT_VIRTIO_BUS_MMIO=y`,
disable PCI and `KFEAT_ENTROPY_VIRTIO_RNG`, then run `make olddefconfig`.
The resulting configuration is saved as `mmio-no-consumer.config`. Retain SMP4.
Clear all `XK_TEST_MODEL_MMIO_*` opt-ins between runs; absent is not the same as
the string `0`, especially for the procfs fixture.

The entropy evidence is deliberately compositional: real-device tests call the
published `HwrngHandle`, while collector tests use an isolated registry and a
counting mixer. Production `register_sources` pairs global HWRNG with
`mix_virtio_entropy`, and the source requests that collector. No dedicated
runtime assertion follows real RNG bytes through the collector into the real
pool. Worker enablement alone is not measured pool credit or random quality,
and worker-disabled destructive fixtures do not substitute for consumer tests.

## Explicit non-claims

No IOMMU, non-coherent DMA, above-4-GiB execution, physical hotplug, physical
GIC/EOI timing, late-response DMA injection, MSI flush/vector reuse or network
shutdown acceptance is inferred. These are not newly invented blocking
requirements for the approved RNG scope. Device registration removal is not
platform-slot retirement. No old `kclass`/DeviceNode facility is removed here.
