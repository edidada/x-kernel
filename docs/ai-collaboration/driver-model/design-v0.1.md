# 新驱动框架：职责与关系设计 v0.1

状态：设计候选，第一部分为职责、对象关系与生命周期；不是可直接实施的完整设计。
依据：已确认的 [需求 v0.2](requirements-v0.2.md)，包含第 6 节设计质量约束。
本稿不改变当前实现文档，不代表以下机制已经实现或获批。

## 1. 三个问题，三个不同生命周期

1. 设备：系统发现了什么对象，它属于哪里；存在不依赖驱动绑定成功。
2. 绑定：哪个驱动在本次管理这个设备，运行资源何时建立和结束。
3. 发布：本次运行提供哪些能力，消费者何时可以进入、何时必须退出。

设备可以经历多次绑定，一次绑定可以产生多项发布。对象引用保活、设备注册、
绑定存续和发布准入不是同一事实；不能用一个 `online` 标志同时表达。

## 2. crate 边界

保留 model、class、os-api 三个职责边界作为候选，不因新增内部概念继续拆 crate。

| 模块 | 负责 | 不负责 | 使用者 |
|---|---|---|---|
| model | 设备注册及关系、驱动匹配、绑定建立与结束、延后探测协调 | 硬件协议、家族数据面、OS 实现、class 注册表 | 枚举/集成代码、驱动 |
| class | 能力发布集合、注册权、消费者句柄、准入与撤销协调 | 设备枚举、驱动匹配、替驱动停止硬件 | 子系统、消费者、model |
| os-api | OS 能力的请求、资源句柄与释放契约 | 设备表、绑定状态机、具体内核实现 | 驱动框架、宿主适配器 |
| 具体总线 | 总线描述语义、枚举和匹配规则 | 通用设备生命周期和家族数据面 | 枚举方、总线驱动 |
| 具体驱动 | 初始化/停止硬件，管理运行数据，使用 OS 契约并发布能力 | 内核实现、全局设备状态裁决 | model 的回调调度 |
| hwrng 等子系统 | 家族接口、家族注册入口和消费规则 | 设备身份、总线枚举、通用绑定调度 | 驱动及宿主消费者 |
| 宿主集成 | OS 契约实现、启动装配、现有节点/事件接入 | 在适配器里再维护一套设备绑定状态 | model、系统启动代码 |

依赖方向：model → class/os-api；子系统 → class；消费者 → 子系统。
宿主集成可以同时依赖契约和内核实现，class 不反向依赖 model。
具体总线实现应离开模型核心，但具体落点随真实接入调查决定，不先拆空 crate。

## 3. model 内部按责任聚合

以下是逻辑 mod 候选，不是必须一概公开的模块列表。

| mod | 拥有的逻辑与不变量 | 接口及边界 |
|---|---|---|
| device | 注册设备的描述与共享身份；对象引用的只读权限 | 对外引用不能直接创建运行权限；不拥有驱动私有运行数据 |
| bus | 通用总线契约及具体实例的关联语义 | 类型描述匹配词汇，实例描述实际归属；不实现 PCI/platform 硬件细节 |
| driver | 驱动描述与回调契约，typed/erased 调用适配 | 驱动实现可用于多个设备；不把某个设备的 Data 放进共享驱动对象 |
| domain | 注册集合、拓扑校验、管理操作协调及唯一状态提交入口 | 其他模块不能各自宣布同一设备已绑定/已注销；对外为管理入口而非整张表 |
| domain::binding | 一次探测/绑定的建立、提交、关闭、回滚与退出协议 | 仅 domain 调用；不成为第二个独立设备管理器 |
| domain::dependency | 等待登记、通知代次和恢复调度 | 不拥有第二份绑定状态；恢复必须重新核对设备及当前尝试 |
| services | 将带设备语义的资源请求交给宿主的契约与适配入口 | 不拥有注册表，也不把宿主类型泄漏给具体驱动 |

probe 和 remove 不再因是不同函数就各自拥有一套绑定状态；它们是同一绑定
协议的阶段，可以有私有辅助文件。注册索引也只作为 domain 的实现细节，
不恢复一个与外部管理接口几乎相同的公开 Registry 包装层。

`device` 与 `domain` 的区别是对象和集合/操作协调，不是两套设备事实。
域持有对象及管理记录，索引引用同一个对象；描述不再从一个记录复制到另一个记录。
最终字段位置在状态与同步设计完成后确定，不在本轮靠字段清单倒推模块。

## 4. 核心角色与名字

| 名字 | 含义与持有关系 | 为什么需要 |
|---|---|---|
| DeviceDescriptor | 枚举方提交的设备描述，注册时转交设备对象 | 输入与已注册对象不是同一生命周期 |
| DeviceRef | 长期持有的设备对象引用，保留身份/描述，不保留运行权限 | 跨解绑或注销仍能识别原对象 |
| DeviceAccess | 驱动回调期间借用的设备访问视图 | 表达临时访问，不暗示另一个独立设备对象 |
| DriverBinding（内部候选） | 一个设备与一个驱动的本次管理关系；拥有成功探测的私有数据 | 与共享驱动实现、长期设备对象区分，重绑定建立新关系 |
| PublicationSource | class 查询本次能力来源的只读契约 | 消费者不必依赖 model；来源有效性不能随下次绑定复活 |
| Registration / Publication / InUse | class 的注册权、消费者句柄、在途使用许可 | 三种权限不同，不能靠 clone 同一种句柄兼任 |

暂不引入新的公共 `DeviceCoreRef` 或通用 Context/Manager 包装层。
当前私有 `DeviceCore` 的最终命名随 device 内部职责确定，不先做代码重命名。
`DriverBinding` 是候选领域名，不以这个名字已经出现就视为用户批准。

## 5. 拥有关系与来源查询

```text
domain ──持有注册对象及管理记录──> device
device ──拥有──> descriptor
domain ──管理当前尝试/绑定──> DriverBinding ──拥有──> driver private data
DriverBinding ──关联──> 同一个 device、选定的 driver
driver private data ──按实际驱动持有──> 资源句柄、发布注册权、运行对象
class ──管理──> publication ──持有──> 只读来源、运行对象
consumer ──持有──> Publication / InUse
```

图中的持有运行对象不代表所有资源都必须放进同一 struct；真正被异步操作
使用的资源必须由其运行对象保活，或在释放前明确等待使用者退出。

来源必须绑定到本次探测/绑定，而不是只读设备级 online。候选机制是每次尝试
创建独立的只读来源支撑对象：它引用设备和驱动身份，并有只关闭、不再开启的
有效性门。探测失败或解绑时永久关闭；下次尝试创建新对象。它不持有私有 Data，
避免 publication → source → Data → Registration 的强引用环。

这里保存的是本次来源的有效期，不是设备注册状态的第二份副本。路径从设备
查询，驱动名从本次驱动关联查询，不在来源里复制字符串。设备当前绑定查询
与旧发布来源查询有不同语义，不能把“上次开始 probe 的名字”当成当前驱动。

此处的“来源有效性门”在后续 Interface 推演中进一步拆清：PublicationSource
仍只读身份，class 的 PublicationScope（候选名）负责准入和排空；model 持有
本次作用域的关闭权。见生命周期设计第 10 节，以该细化为当前候选，避免把
只读来源 trait 变成退出控制接口。仅增加一个布尔门不足以证明退出完成。

## 6. 生命周期交接

| 场景 | model 的责任 | 驱动/子系统的责任 | class 的责任 |
|---|---|---|---|
| 注册 | 校验归属及关系，纳入设备集合 | 枚举方提供真实描述 | 无 |
| probe | 独占本次尝试，选择驱动，提交成功或处理失败 | 申请资源、初始化硬件、构造可安全回滚的运行数据 | 管理实际发生的发布 |
| probe 失败 | 使本次来源不可再用，协调回滚/依赖等待，不提交绑定 | 停止已启动活动，释放未提交资源 | 撤销失败尝试产生的发布，保护在途使用 |
| unbind | 关闭本次来源，协调 remove 和资源收尾；保留设备注册 | 停止硬件、唤醒或等待操作，撤销发布 | 停止新使用并完成相应发布收尾 |
| rebind | 为同一设备建立新的尝试/绑定 | 重新初始化，不复用失效运行权限 | 旧句柄失效，新发布独立 |
| unregister | 禁止新绑定/挂接，协调相关退出，结束设备注册 | 总线/驱动按真实所有权撤销其创建的下游对象 | 不把设备纯元数据引用视作阻止注销的许可 |

不能通过字段析构顺序替代 probe 失败和 remove 中停止 IRQ、队列、工作项的义务。
父子描述关系不自动等于“父绑定拥有子设备”；由控制器创建的下游与静态拓扑
必须分开调查。不会用一律叶子限制跳过这项责任分析。

## 7. 取舍与反例检查

- 不把所有运行资源放到长期设备引用中：否则引用保活会阻止正常解绑清理。
- 不把 class 合并进 model：消费者不应承担设备枚举和驱动绑定的依赖。
- 不复制设备元数据创建绑定快照：绑定来源只关联权威对象，保留的是本次关系。
- 不直接让 source 强持有整个绑定及 Data：会造成循环或让旧句柄拖住全部资源。
- 不沿用一个在线标志关后再开：会使旧发布随重绑定恢复有效。
- 不为每个名词新建 crate：内部 binding/dependency 共享管理不变量，应作为私有 mod。
