### R1-01：设备注册与绑定生命周期闭环

贯穿 model 管理入口、每设备 host mutex adapter、类型化 Data 与外置 UT。
展示同一设备可解绑后重绑，注销后旧引用不能再次绑定；竞争操作只清理一次，
不同设备管理不被全局回调锁串行。非法上下文/同设备重入在回调前拒绝。
移除通用 parent 递归与 remove_retryable 作为正常协议，明确实际下游由总线管理。
保留已有匹配行为；旧 provider/class 消费者所需兼容入口暂留，不提前大扫除。

### R1-02：延后探测的确定性进度闭环

通过公开注册/依赖通知路径复现并验证两个窗口：通知早于 Deferred 登记；
执行者准备退出时新工作入队。加入注销后迟到工作、无第三次通知也能推进、
同设备不重复并发 probe。私有测试同步点不变成生产公共 API，不增加执行器。

### R1-03：hwrng 注册、消费、同步注销闭环

从 register 到受控 read，再到 prepare-first 同步 unregister，接入真实
host CompletionWait adapter 并用受控 provider 验证在途排空。只在准备
成功后修改状态，removed 在排空后同步发出；非法入口无副作用，Drop 不
自动注销/等待/panic，残留注册可观察。整合已确认命名和 registration mod。
保留有真实旧调用者的最小桥接，维持构建和旧 RNG 启动；不把桥接计为 R10。
读取等待原错误测试继续有效，不将任意 RngCompletion 强制当可靠排空实现。

### R1-04：模型绑定到 hwrng 发布的端到端回滚

测试驱动通过 DeviceAccess 和本次来源注册 hwrng，模型解绑调用其显式
清理；注入发布前后 probe 失败、成功交付后的模型拒绝。只读驱动身份
作为唯一名称来源，与任意 ops 析构分离；A/B 及同驱动重绑保留旧句柄验证。
覆盖 Data/注册权/runtime 资源的所有权，检查退出后最后引用不重复清理。
此票不使用假设备结果冒充真实 MMIO 验收。

### R1-05：entropy 从旧来源转到新来源

复用 R1-03 的句柄/通知，用两个可控来源运行真实采集工作：A 空闲撤销、
读中撤销、B 先到、A 迟到通知、暂无来源后恢复。固定采集 work，保留需求，
不依赖新 getrandom/第三次注册；终止失败实例不被重复发现重启，记录不无界增长。
维持来源过滤、Host trust 和暂时失败退避行为；回调不等工作/设备管理锁。

### R1-06：VirtIO 实例 DMA 闭环

在正式库源码工作区交付按实例后端分配、share/unshare、释放的一条闭环，
用两个后端验证 ring、indirect 与请求不串用且失败回滚配对。保留旧静态 Hal
调用兼容，不通过全局当前设备/TLS 注入。纳入主仓依赖固定版本/来源，确保
单票可复现构建，不能只修改 cargo registry 缓存或交付空 trait。
host 的真实设备约束接入在 R1-08 验证，本票不冒称已有硬件 DMA 证据。

### R1-07：驱动停止与请求回收闭环

在 R1-06 的后端形状上扩展正式 VirtIO 库及 RNG 停止路径：拒绝新提交、
唤醒 read、reset 确认、同步 IRQ、回收 pending、解除映射一次。用可控
transport/IRQ provider 覆盖无完成、完成/取消竞争、迟到 IRQ、共享 action
及旧 runtime 引用。对应真实硬件验证留给 R1-08，不能以 mock 宣称硬件已安全。
G-IRQ 必须完成 review/交付后才将同步释放保证作为已验收基础。

### R1-08：真实 MMIO RNG 纵向接入

贯穿固件枚举、新旧唯一分流、model、host MMIO/IRQ/实例 DMA、具体 RNG、
hwrng 和 entropy。确认目标 MMIO Version=2，不沿 attach_legacy 路径。
验证真实采样、pending 时解绑、保留旧句柄重绑、设备注销及双实例隔离；
记录节点/事件基线，回归旧 PCI RNG。真实接线与最小验收在同票内，不拆成
无法单独演示的“只写 host 接口”和“以后再接硬件”两张横向票。

### R1-09：收缩兼容层及整体验收

在所有新链路可用后删除无调用者的 base/class 和过渡接口，更新依赖及文档；
仍有旧调用者的桥接必须保留或在本票明确迁移，不能机械删除旧 kclass。
运行 R01—R13 对照验收、定向 UT、平台 build/clippy/fmt、真实 MMIO 生命周期
和受影响旧设备/节点事件回归。各票早已各自验证，本票不是首次集中补测试。
生成确切基线、命令和结果记录，不将历史 PCI 结果当作 MMIO 证据。
