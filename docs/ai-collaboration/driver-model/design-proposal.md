# Linux 对齐驱动框架：整体设计评审稿

状态：整体评审稿 R1；正常路径合同与实施验收条件已汇总，待人工整体验收。
不是已批准实现方案，不授权编码；未执行目标实现测试。
实现调查基线：driver worktree 的 `269fe04a2`，含尚未提交的命名调整现场。
需求依据：[R01—R13](requirements-v0.2.md) 与 README 所记录的后续确认。
证据及方案演进：[调查记录](design-review.md)。本稿描述目标，不描述当前代码已完成。

## 1. 目标与边界

以 Linux 的设备注册、驱动绑定、解绑、设备注销职责为基础，以一条真实
VirtIO MMIO hwrng → entropy 链路验证。允许适配内部接口，保留已有正确功能。
不迁移全部驱动，不实现完整 PM、物理热插拔、动态模块、Linux 全套 class ABI。

已确认的关键规则：

- 设备身份不等于一次绑定；普通引用保活不等于硬件访问权限。
- class 是设备分类，不是泛型服务生命周期；hwrng 自己拥有 provider 注册。
- remove 完成驱动退出，不建立通用 Failed/Retrying/整树准备事务。
- 凭证 Drop 不注销、不等待、不默认 panic；遗漏注销留下注册，是 bug。
- 消费者 Drop 不停机；不默认 DeferredArc，不新增后台补做退出。

## 2. 模块及依赖

| 位置 | 拥有的责任 | 不负责 |
|---|---|---|
| drivers/base/model | 设备身份/关系、注册、匹配、绑定、单设备管理及延后探测 | 家族读取、硬件 reset、消费者排空 |
| drivers/base/os-api | OS 中立的 MMIO、IRQ、DMA、时钟等能力合同 | ktask/kirq 等宿主实现、设备模型第二份状态 |
| drivers/subsystems/hwrng | 注册表、唯一注册权、消费者句柄、准入及在途排空 | 匹配、设备停机、entropy 信任策略 |
| drivers/devices/virtio | 本次驱动运行对象、请求、停止读者和硬件收尾 | 通用退出协调器 |
| host adapters / kdriver | 实现能力合同；固件枚举接入、新旧分流 | 向可复用驱动暴露宿主 API |
| util/entropy | 选源、采样需求、熵处理及来源失效后的重选 | 取得注册权或延长硬件运行寿命 |

新 base/class 的消费者迁出后删除旧泛型层；不删除旧 contracts/kclass 或
device_node，不为空的未来 class 需求建立占位 crate。

model 保留 device 目录按描述、共享对象、回调访问聚合；管理注册、生命周期、
探测调度属于同一模型内的私有 mod，不按每个类型拆 crate。hwrng 保留
lib.rs（公开能力）、registration.rs（注册生命周期）、completion.rs（等待合同）。
单设备管理锁合同归 model 的宿主服务模块，排空合同归 hwrng；暂不泛化。

## 3. 对象、权威事实与所有权

| 对象 | 内容与使用者 | 生命周期 |
|---|---|---|
| DeviceDescriptor | 枚举事实：bus instance、bus data、parent、可选 DMA 约束 | 创建设备前的输入，随后由设备对象拥有 |
| DeviceCore / DeviceRef | 共享设备身份与描述；引用用于关系、查询、管理定位 | 可跨解绑存在；注销后仍可保活但不能重新绑定 |
| DeviceAccess | probe/remove 期间的受约束借用及资源申请入口 | 不可作为长期硬件访问凭证 |
| 当前绑定 | 驱动实现引用及其 Data | probe 成功交付后归模型；remove 后释放 |
| 只读驱动身份 | 唯一驱动名，不带 ops、Data 或硬件资源 | 可被旧来源保留；新类型名称待随本稿命名评审 |
| provider 来源 | DeviceRef + 本次发布的只读驱动身份引用 | 不读取设备后来绑定的驱动来解释旧 provider |
| HwrngRegistry | 已注册 provider 强引用及发现订阅 | 子系统所有；不使用公开全局 publication ID |
| HwrngRegistration | 唯一注销权 | 驱动私有 Data 持有；不克隆给消费者 |
| HwrngHandle | 受控 read/is_failed、可用性及实例比较 | 只能操作其原 provider，不转接新绑定 |

设备只声明一个总线实例归属，类型从该实例提供。parent 表示拓扑，不自动
授予递归卸载权；总线/控制器负责先停止自己的枚举，再退出其拥有的下游。
无 DMA 的设备不伪装成默认 DMA 能力。名称/path 不在多个对象中缓存成权威事实。

只读身份与驱动实现分开：注册时拆分 DriverDesc 输入，注册实现也从同一身份
读取名字；不再同时保留完整带 name 的描述副本。旧来源不保活任意 ops 的 Drop。
当前 &'static 驱动名不构成未来动态模块卸载设计；本轮不新增模块 pin。

## 4. 管理接口与串行化

下表是行为接口；未确认的新函数/错误变体名称不视为已经定名。

| 操作 | 成功与失败语义 |
|---|---|
| 注册设备 | 验证枚举事实、准备管理锁后可见；失败不留下半注册设备 |
| 匹配/尝试绑定 | 无匹配或 Deferred 不结束设备注册；probe 错误先完成驱动回滚 |
| 解绑 | 有绑定则 remove 并解除关联；无绑定不重复回调；设备仍注册 |
| 注销 | 先结束绑定，再撤销注册和调度资格；旧引用不能复活 |
| 重复注销 | 同一域已注销对象不再次清理；跨域对象明确拒绝 |
| 元信息查询 | 不授予 Data 或硬件资源访问权；不以全局表锁执行任意回调 |

同设备 probe/unbind/unregister 由独立睡眠管理锁串行，获取锁后复核状态。
非法上下文在状态改变前返回错误；同锁重入在调用回调前返回错误，不自动绕锁。
不同设备不因全局回调锁互相排斥。全局注册/调度锁只保护短状态操作。

host 锁采用对象安全的 `run_locked(&self, &mut dyn FnMut()) -> Result<…>`
形状：同步执行一次回调，不保留它，返回前解锁；host 以现有 mutex 的局部
guard 实现，不每次分配类型擦除 guard。锁对象在设备发布前构造。
ksync 当前竞争路径仍通过 block_on 分配唤醒对象；本稿不承诺整个管理流程
无分配，也不顺带重构 mutex。若要求改变，应列独立宿主前置。

回调必须返回时恢复其调用上下文，不能同步等待需取得当前锁才能结束的操作。
父子锁规则由实际总线定义，不由 model 生成整树事务或根据任务 ID 绕锁。

## 5. hwrng 接口、等待与 Drop

- register 在条目可见前准备可靠排空能力，成功返回唯一注册凭证。
- read/is_failed 只经句柄进入；同一短锁保护关闭标记和在途计数，许可为私有
  实现细节。runtime 调用、等待和订阅回调不持注册表锁。
- unregister 借用凭证，先完成等待准备，再关闭准入、撤下可用条目并等待
  在途为零，完成后标记凭证已注销；已成功注销的再次调用不重复清理。
  注销订阅通知在排空之后、unregister 返回之前发出；该时机已获局部确认，
  依据见第 11 节。
- 正常错误只允许发生在等待准备、首次修改状态之前，保持注册及凭证不变。
  排空期间不调用任意订阅回调；不能接收一个在修改状态后返回普通错误的
  provider，再由 remove 补偿它。具体宿主合同及确认范围见第 11 节。
- 注册表强引用 runtime；遗漏注销的凭证 Drop 不改表、不等待、不调用
  runtime/hook，可作上下文相容的诊断。注册残留并非成功解绑。
- runtime 真正拥有 read/IRQ 会使用的资源；强引用一个壳并不能保活外部 guard。

可靠排空与 read 等待合同分开：read 保留准备失败语义；可靠排空在合法上下文
中不能因 NoMemory、超时、信号中断而返回。构造可失败，必须在注册前完成。
host 复用 WaitQueue/CompletionWait；两类等待使用各自队列，不新增同步算法。

普通 Arc 满足当前对象内存寿命；显式退出先解除活动资源，最后引用释放只
处理剩余状态。provider、来源与等待适配器的最终析构均需审计，不以 Send+Sync
推导析构可睡眠或任意上下文安全。

## 6. 正常、失败与并发退出

正常 VirtIO RNG remove 的唯一目标顺序：

1. model 保活 Data；驱动在请求锁下停止新读写，锁外唤醒读者。
2. 显式注销 hwrng，排空已准入操作并发出注销订阅通知；消费者长期引用
   不阻止排空，通知回调不承担唤醒这些操作的责任。
3. 在请求锁下取出完整请求资源，停止后的 handler 不再访问 transport/queue。
4. 锁外 reset 并确认完成，期间保留 MMIO、队列、buffer、DMA 和 IRQ guard。
5. 锁外同步注销本 IRQ action，排空 handler 包括其通知尾部，不动共享 line 的其他 action。
6. 回收 pending token、解除映射并释放资源；取消数据不得作为熵；remove 返回。

probe 自己返回错误：自身收尾，不等核心补调 remove。已发布后失败：同一
退出 helper 先撤销发布再释放硬件。probe 已成功但模型后置步骤失败：核心
调用 remove 后再丢弃 Data，不允许直接 drop 成功运行对象。

正常完成与取消由同一请求状态决定唯一回收方。先 reset 再回收遵守 VirtIO
停止保证；软件 IRQ 排空是另一独立条件。坏硬件拒绝停止不承诺有限退出时限，
也不因超时释放仍可能被访问的 DMA。不建立通用停机失败恢复状态机。

## 7. 延后探测及 entropy 进度

延后探测保留按依赖的通知代次保护，覆盖“检查依赖后、登记等待前”窗口。
另将 pending 入队、执行权认领、空队列时交出执行权放在同一短锁内，避免
最后一次检查后新请求被遗留。注销关闭调度资格，迟到工作取管理锁后再次检查。
调度只派发，不以单个全局 probe 执行者替代单设备管理锁。

entropy 固定一个采集 work，来源变化只更换句柄，不创建每来源退休协议。
初始化先准备 work，再订阅可用/撤销，再枚举。事件触发重查，不能按旧事件
直接清空后来安装的选择。锁外读取；未满足需求在来源撤销后交给新来源。
无来源时保留需求而不忙等；后续通知即可继续，无需第三次注册或新 getrandom。
终止失败实例不因重复发现而重启；失败记录仅覆盖仍注册实例，撤销后清理。
仍按现有 virtio-rng 过滤与信任策略；不借迁移扩大熵来源范围。

## 8. 真实接入、兼容与前置交付

目标为 aarch64 QEMU 的 modern VirtIO MMIO RNG（运行时确认 Version=2）。
固件发现设备类型后，在旧 kdevice 注册之前唯一分流到新模型；空 slot 不注册。
不能先旧注册再建立新模型镜像；其他 VirtIO 设备继续旧路径。

| 前置交付 | 需要的合同与验收 |
|---|---|
| Completion | 已合入；复用，不重复开发；可靠等待适配仍要验证 |
| IRQ 同步 | 独立验收工作已有证据；接入时验证本 action 排空和共享 IRQ 隔离 |
| 管理锁/等待 adapter | 上下文拒绝、回调执行次数、无全局锁跨回调、等待节点退出 |
| 实例 DMA | queue/ring/indirect/request 使用同设备后端；不靠全局当前设备 |
| VirtIO 停机/取消 | reset 完成判据、pending 唯一回收、映射配对；正式库源码交付，不改缓存 |
| 枚举/host 接线 | 真实 MMIO、IRQ、DMA 事实及单一管理者，非 attach_legacy 桥接 |

已检查的兼容清单：/dev/random 与 /dev/urandom 是 entropy 池入口，不随
单个 RNG 撤销消失；现有 DeviceNode 的 Input/Drm 投影及 uevent 保留。
静态调查未发现现成 /dev/hwrng、rng_current、rng_available，不能冒充已有 ABI，
也不为此次迁移补齐 Linux ABI。实际迁移仍需固定启动配置采集运行基线。
解绑只改变绑定；设备注销才产生相应设备消失语义。
之前 63 项回归用的是 PCI RNG，不作为目标 MMIO 解绑/重绑证据。

## 10. 与 Linux 的对齐和必要差异

- 对齐正常注册/绑定/解绑/注销职责及 virtio-rng 的显式 remove 顺序。
- 用类型化 Data、Arc 句柄和受控方法表达 C 的对象及调用责任，不照搬指针 API。
- 外部非法管理上下文用 Result 拒绝是额外防御，不宣称 Linux 同样返回错误。
- 不从 Linux WARN/BUG 推导统一 panic；也不从 devm 推导任意 Drop 自动停机。
- 注册表强保活运行对象是 Rust 所有权选择；遗漏注销仍可能泄漏，并非自动恢复。

## 11. 注销等待的具体收敛与已确认的通知时机

本文已集中职责、对象、接口行为、生命周期、前置交付及 R01—R13 验收。
不是新的需求，也不把此前局部确认扩展为整体验收。新内部类型的准确命名
随接口评审确定，不在未确认时进行机械重命名。

核对现有 host：HostRngCompletion::wait_until 已经先调用
CompletionWait::prepare，再执行谓词等待；prepare 的错误发生在谓词
第一次调用前。目标可靠排空合同固定这一顺序，不只提供一个先检查、
随后仍可能失败的 can_wait 快照。

目标 unregister 在私有谓词的首次执行中关闭准入并撤下条目，然后检查
在途计数。后续调用只复查计数。该谓词只修改 hwrng 内部状态，短锁退出
后才返回；不调用订阅者、驱动或可能改变执行上下文的任意业务代码。
宿主在首次谓词调用前可返回 InvalidContext；开始调用谓词后不返回
普通准备错误，必须等到谓词成立。这是可靠排空 provider 的合同，不
改变原 RngCompletion 的错误语义，也不创建可转移等待凭证或准备事务。

移除注册表项时凭证/局部引用保持 provider 存活；被移出的引用在锁外
处理，不能在谓词内触发 runtime 的最终析构。最后一次在途操作退出
发布计数变化后通知；登记与复查复用 CompletionWait，覆盖通知早于
真正 park 的窗口。排空返回后才标记注销完成，运行注销订阅通知。

这里区分两个不同通知：驱动停止时唤醒阻塞 read 必须在排空前；hwrng
发给 entropy 等订阅者的“来源已注销”事件不负责唤醒 read，可在排空后。
后者只要求重查选择，不需要等待旧 read 自己触发一次失败才感知撤销。

### 外部行为调整及确认范围

当前泛型 class 的 removed 回调先于在途排空；目标 hwrng 改为排空后，
并仍在 unregister 返回前同步发出。检查到的 hwrng/entropy/kdriver 生产
代码尚无 subscribe_removed 调用者；旧 class 的通知测试不因此擅自改写。
迁移后 entropy 使用新语义。“暂无消费者”是影响调查，不是批准依据。

确认依据：向用户明确展示“准备等待 → 关闭准入并排空 → 注销通知”的
顺序，并说明驱动唤醒仍在排空前、通知不代表硬件已释放，询问是否认可
将订阅通知放到排空之后；用户回复“okay”。确认覆盖这项时机调整，
不扩大为对本稿全文、具体 Rust 实现或 tickets 的批准。

收益是等待关键区间不运行任意业务回调，订阅者获得明确的“业务调用已结束”
语义。代价是通知晚于关闭准入；若读者不退出，通知也不会到达。该情况必须
由驱动停止/唤醒机制解决，不能依赖 removed 回调倒过来帮助 unregister 排空。
通知不代表 reset、IRQ 注销、DMA 回收都已完成，这些仍属于后续驱动收尾。

### 仍须如实限定的边界

以上消除符合合同的等待 provider 在状态改变后返回错误的正常路径，不
声称任意有 bug 的 host/订阅者都能安全恢复。订阅者返回时必须恢复上下文，
不得递归管理当前设备；目标 entropy 回调仅更新选择状态、提交 work，不
等待旧工作，也不取得设备管理锁。通知后的硬件收尾仍需按此调用链审查。
驱动在 remove 中调用注销时，非法上下文不是合法资源失败；必须在具体
实现审查中证明其锁已释放、宿主调用保持上下文，不能统一 expect 任意错误。

验收增加：等待准备失败时谓词零次调用且注册不变；首次谓词关闭入口；
最后读者结束前无 removed 事件；事件中旧句柄已不可进入；回调不阻碍读者
退出；通知发生时尚未完成硬件收尾也不授予订阅者访问 runtime 的权限。

其余未完成项是明确的实施前置和验证交付，不要求设计阶段先写完底层。
通知时机已经确认；具体上下文链路的设计核对见第 13 节。提交整体验收后再执行 to-tickets，
展示纵向切片和阻塞边，确认后逐票落地。此稿不创建票、不提交或推送代码。

## 12. 本轮交叉核对记录

| 核对项 | 结论与验证边界 |
|---|---|
| 排空是否反过来依赖 removed 回调 | 不依赖。第 6 节由驱动先停止并唤醒 read，订阅者不负责让 read 退出 |
| entropy 是否必须提前收到撤销事件 | 不必须。旧 read 因驱动停止返回，需求仍由采集工作保留；排空后通知负责补足空闲来源失效发现 |
| A 的迟到事件会否清掉 B | 事件只触发集合重查，不按旧事件直接覆盖当前选择 |
| 通知时硬件是否已经释放 | 没有这个保证。订阅者只能使用已关闭的受控句柄，不获得 runtime 或停机权 |
| 等待准备错误是否改变注册 | 不改变。首次谓词调用前返回；不得把旧的“先关闭再 prepare”实现直接搬来 |
| 可失败 read provider 能否直接用于排空 | 不能。保持两个合同；共享实现不代表任意测试替身均符合可靠排空要求 |
| Drop 是否仍暗中恢复旧行为 | 目标不恢复。当前代码仍委托旧 class，实施时必须删除自动 withdraw，旧 UT 需要按已批准语义迁移 |

以上是接口与顺序的一致性核对，不是生产实现或运行验收。下一项具体审查
范围固定为 remove 调用前后执行上下文：驱动停止/通知 helper、可靠等待
adapter、注销订阅者及随后 IRQ 释放。无需再讨论已确认的 Drop/通知时机，
也不增加新的异常清理框架；若该调用链仍有可达普通错误，必须明确指出。

## 13. Remove 上下文链路的设计审查结论

### 证据与目标约束逐段对应

| 阶段 | 本地证据或目标操作 | 必须维持的不变量 |
|---|---|---|
| 进入管理回调 | 第 4 节 host 管理锁 adapter；尚待实现 | 先拒绝非法任务上下文，再获得睡眠锁，不带 IRQ-off/RCU 保护调用 remove |
| 停止读取 | 目标驱动在请求锁下置 stopping，退出词法锁作用域 | prepare 前没有残留请求锁；停止只改状态，不调用任意清理回调 |
| 唤醒读者 | rng_completion.rs::notify → WaitQueue → CompletionWake::notify | 在请求锁外；宿主短锁/调度锁使用局部 guard，不将 IRQ/preempt 保护带回调用者 |
| 准备排空 | ktask CompletionWait::prepare | 无分配；只因缺少合法任务上下文返回 InvalidInput；先于首次谓词调用 |
| 关闭并排空 | 第 11 节私有谓词 + CompletionWait::wait_until | 私有谓词恢复短锁、无订阅回调；准备后没有普通可失败登记步骤 |
| 发送 removed | 目标 entropy 更新状态、提交固定 WorkHandle | 不 join/shutdown 工作，不等设备管理锁，所有局部锁在返回前释放 |
| reset | 正式 VirtIO 库前置合同 | 不持请求锁等待完成；不能遗留禁抢占/关 IRQ 状态 |
| 释放 IRQ | kirq 同步接口及相应 host release hook | 取出 guard 后释放 irq_guard 锁，在可睡眠上下文同步注销；仍保活运行对象 |

调度唤醒可能发生切换，但正常恢复会回到同一等待任务；它不是任务变成 IRQ
上下文的理由。CompletionWait 的任务绑定禁止跨任务转移。对于任意新 host
实现，上述是必须验证的合同，不用当前一个实现的成功证明所有实现正确。

### 错误分类与 void remove 的含义

1. 可预期的构造、资源申请失败：发生在 probe/发布准备阶段，显式回滚并
   返回错误。不能用 void remove 承接这些正常失败。
2. 外部非法管理/注销上下文：在任何本次生命周期修改前返回错误。可靠
   排空不是简单的 can_wait 快照，而是在首次谓词前实际准备好等待。
3. 正常 remove：管理上下文合法，上表每段保持这一条件，可靠等待不引入
   新资源失败，因此没有业务上的“排空失败后仍继续释放”分支。
4. 实现破坏上述不变量：属于驱动/host 实现缺陷，不是一个支持的运行状态。
   不承诺恢复，不新增通用错误状态机；不得吞掉错误、返回假成功或把它
   伪装成已排空。代码审查必须追溯到具体破坏点，而非只看接口前置注释。

仓库已有的对应做法是 kirq::wait_for_virq_in_flight：公开边界拒绝非法
上下文，内部等待点依据“已验证、期间只经过会恢复上下文的局部锁”的
具体证明使用站点级不变量诊断。这是证明形式的参考，不是驱动新代码的
自动豁免，也不是重新批准遗漏注销时 panic。新的 assert/expect 若确实
需要，必须单独给出同等级调用链证据并按 CG-021/024 review；没有证明
就不能合入，更不能对任意公共 KResult 批量 unwrap。

还需如实记录现有差异：旧 device-res host 的 release_irq 在 kirq 返回
错误时仍有带 TODO(cg) 的 panic；不能称为已消除所有旧 IRQ 析构诊断。
新目标 adapter 必须在明确的显式退出上下文中释放匹配 guard，并验证
shared-action 与普通 IRQ 路径；不得直接复制这个 TODO 当作新接口设计。

### 自查结论与交付门槛

此前的“状态改变后，任意订阅者影响等待准备”的正常路径缺口已通过
准备前置、私有谓词及通知后置消除。对符合合同的目标实现，void remove
与同步注销不再需要一套可恢复的退出失败协议。设计不承担自动修复任意
驱动 bug 的保证；这与已确认的显式退出责任一致。

这个结论是设计合同及现有基础能力的审查，不是宣称尚未编写的 remove、
host adapter 或库扩展已经通过验证。实施票必须把上表作为审查清单，
加入非法入口无副作用、prepare 失败不调用谓词、退出各点锁/IRQ 状态、
通知/等待交错和 IRQ 在飞排空测试。发现新的合法失败渠道则退回修订设计，
不得靠添加 panic、跳过 cleanup 或放宽测试完成票。

整体设计现提交人工评审，评审范围为本稿第 1—13 节；调查记录只承接证据，
不恢复其中已撤回的方案。已确认的 Drop 与通知时机不重复审批。尚未实现的
能力列为第 8 节前置，真实硬件与兼容性证据列为第 9 节交付，不冒充设计
阶段测试结果。整体通过后才执行 to-tickets 并确认粒度/依赖；本轮不编码。
