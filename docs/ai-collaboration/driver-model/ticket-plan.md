## 各单元验收与边界

### 01：完善现有 Completion 的同步等待

需求与实现范围见 [Ticket 01](ticket01-requirements.md)。内核同步等待与旧调用方
迁移已经合入；下文保留早期设计讨论过程，不再作为重新实现原语的指令。
原计划 host 与 os-api 的接入闭环仍需在 class 局部设计中核对和补齐。

覆盖 P1、R08/R09。先对照 Linux 和已有同步/任务能力提交最小局部设计，再实现
host 与 os-api 的一条调用闭环，不仅交付空 trait。复用现有 Completion 的完成
状态语义，不把“已有完成机制的等待登记缺口”误写成没有 completion。

用户提出参考 kwork 的外部存储生命周期，考虑重构 completion。本地核对确认
borrowed Work 内嵌 pending 节点，由外部保有稳定存储，队列借用节点；准备后
提交不逐次分配。不能扩大解释为 kwork 的初始化、拥有型封装或所有等待都不分配。

优先评估：completion 等待者也由调用方提供稳定节点，完成对象只维护状态及
节点关系。同步 wait 可在内部封装栈上节点，使普通驱动只调用等待接口，不需要
自行管理 Pin/裸指针或执行显式摘链。这与 Linux swait 的调用方节点模式一致，
不是要让 completion 依赖 kwork，也不复制 work 的执行/取消状态机。

节点稳定地址只解决移动问题，不证明其可释放；局部设计必须证明登记、唤醒
访问与退出摘链的生命周期闭合。尤其不能让允许迟到的通用 Waker 持有栈节点
裸指针，也不能把等待队列扩容改成每次 Box 节点后声称消除了分配。
现有 PreparedTaskWait/block_on 的 waker 创建仍可能分配，必须单独核对；
不得只改链表就声称整个同步等待路径无分配。现有 poll 接口如何兼容由局部设计
给出，不默认重写全部 PollSet。上述是候选方向，尚未授权实现。

- 完成早于等待、登记并发完成、多等待者、虚假唤醒均正确。
- IRQ 通知不分配/不睡眠；等待者返回后无失效访问，内存可见性有依据。
- 区分对象创建与等待登记的失败策略，不改全局 OOM/panic 策略掩盖失败。
- 不重写调度器、全部 poll 用户或全部 WaitQueue；不新增通用执行器。

### 02：IRQ 同步释放

覆盖 P2、R06/R08。用实际 IRQ 等待桥证明前置能力能消除当前释放路径的缺口。

- handler 在途时释放必须等待；释放返回前回调依赖资源仍有效。
- 错误上下文在不可逆移除前被拒绝，重复释放结果明确。
- 共享 IRQ 的其他 action 不被误关；回归现有整线同步/禁用语义。
- 不预设增加 action 计数或重写 dispatch；出现额外机制需求先报告并设计。

### 03：hwrng 服务注册与同步注销

覆盖 R05/R06/R08。按 Linux hwrng 模型，由子系统管理 provider 注册和可发现性、
读取准入、在途操作及同步注销。真正 class 分类的是 device，不是任意服务 T。
盘点旧泛型 class 的生产调用方后迁移，不机械改名或保留无真实需求的通用层。
具体局部设计以 hwrng-lifecycle-design.md 为准，替代早期统一 class 排空方案。
01B 优先复用已有 RngCompletion 及真实 host adapter，验证排空接入；不把新增
os-api trait 或默认引入 DeferredArc 当作完成条件。

- 使用已确认的 HwrngRegistry、HwrngRegistration、HwrngHandle、HwrngDevice；
  注册与使用生命周期聚合在 registration.rs，私有许可不暴露给消费者。
- 注册凭证与消费者句柄权限分离，关闭后新操作失败，旧操作可以退出。
- 显式注销完成后在途操作归零、子系统注销动作完成；锁外通知，上下文正确，
  不迁入没有真实使用者的通用 ClassHooks。
- 长期保留旧句柄不拖住已结束的活动资源；最后许可释放不内联睡眠清理。
- 移除来源在线判断与强制组级准入，独立发布方保持可用；旧 model 调用通过
  最小兼容接线保持可构建，完整绑定语义在 04 改造，不在此票静默实现一半。

### 04：单设备生命周期

覆盖 R01/R02/R03/R05。以可控测试驱动贯通注册、匹配、发布、解绑、重绑和注销。

- DeviceRef 身份不因解绑变化；当前驱动事实只来自绑定记录，不复制可变名称。
- probe 发布后失败先完成回滚；probe 与注销竞争不丢弃活动 Data。
- 同设备管理串行，回调锁外；重复退出不重复 remove，旧发布不会访问新资源。
- 保持普通 probe/remove；机械命名/目录调整与行为变更分开提交，每步可验证。

### 05：下游所有权

覆盖 R02/R06/R08/R13。测试控制器和孩子，不引入真实 PCI/I2C 新子系统。

- 只因 parent 相同不误删非本次绑定拥有的注册。
- 子 remove 可调用仍有效的父服务；不提前关闭父能力，不持其事务锁等待孩子。
- 注册提交与父退出交错时，不漏掉成功注册，不接纳旧绑定迟到结果。
- 不引入整树认领、特殊子退出计划；注销职责在总线/控制器，模型只管单设备。

### 06：延后探测

覆盖 R04/R08。不创建通用 provider 生命周期系统。

- 依赖先到、登记后到、交错到达，都最终得到应有的重试。
- 重复通知不导致并发 probe，执行前检查注册和绑定状态。
- 注销后迟到通知无效；已有测试用 provider 能力有明确保留/迁移说明。

### 07：DMA 发现事实

覆盖 P3、R02/R09。用实际 QEMU DT 与可控固件输入验证转换。

- 所选平台 mask/offset/coherency 有依据，不从属性缺失直接推断全范围可用。
- DMA 配置缺失、无法表达的多段范围、区间溢出有明确结果。
- 固件层不依赖 model；设备描述持有最终约束，转换不产生多个可变事实源。
- 保持现有描述构造接口可用，此票不以重命名依赖 04，也不扩大到全平台迁移。

### 08：真实宿主资源

覆盖 P4、R09。选择新模型测试设备获取真实 provider 能力，而非只给 MockServices
增加方法；能力实现/安装可复用已存在的 host 层，不另建杂项服务容器。

- MMIO/IRQ/DMA 的创建、失败回滚和释放具备可验证路径。
- 两设备注入不同 DMA 视图，分配/映射与释放不串用；校验完整区间。
- 可移植驱动不直接依赖 host 类型，provider 安装先于实际 probe。
- 不借此迁移所有旧 device_res 用户；生产 hwrng 接线由 11 验收。

### 09：VirtIO 实例后端

覆盖 P5、R07/R09/R11。库内用两个可记录分配/释放的后端完成 queue/request 闭环。

- ring、请求和 indirect table 都使用实例后端，无 TLS/全局当前设备。
- 分配/映射部分失败完整回滚，不向设备提交半成品 descriptor。
- 保留静态 Hal 默认入口并回归 queue、RNG 及项目已有 blk/net/input 调用。
- 补丁交付到正式库源码和可复现依赖，不编辑 Cargo registry 缓存冒充交付；
  实施前确认库源码工作区及版本交付方式，未授权不向外部仓库推送。

### 10：VirtIO 停机回收

覆盖 P6、R03/R06。使用 09 的真实映射所有权，不能以计数 mock 代替资源回收协议。

用户已确认作为真实 hwrng 退出/重绑的 VirtIO 前置需求，不在 base/class 中补偿。
固定版本 kvirtiodrivers 0.13.5 有 queue_unset 等析构动作，但缺少显式停机后
取消 outstanding RNG 请求的公开契约。实施在正式 VirtIO 库源码及其驱动接线中
完成，不修改 registry 缓存冒充交付；源码工作区和依赖交付方式沿用 09 的要求。

必要能力：停止新提交，确认目标 transport 不再访问请求/队列，随后回收未完成
token 的 descriptor、DMA 映射及缓冲区所有权。接口命名和具体同步算法在局部
设计时确定，不预设新增框架、DeferredArc 或通用解绑失败状态机。

- pending 请求无新 used entry 时，确认停机后仍能回收对应 buffer/映射。
- 完成与取消竞争只消费一次；取消的数据不能被当成有效熵。
- 迟到 IRQ 不访问已回收队列；无法确认停机时保留资源、不宣称成功退出。
- 证明目标 MMIO transport 的停止契约；不把同名 reset 当成所有传输的相同保证。
- 无在途、正常完成、无 used entry 的 pending、完成与停机竞争均恰好回收一次；
  重复收尾不会双重 unshare/free，构造中途失败可以按合法回滚顺序解除资源。
- 未证明停止前不得释放 DMA；底层异常处置归 VirtIO/transport，不扩展成 model
  的失败绑定和重试事务。正常 remove 仍须履行已确认的完整退出责任。

依赖保持 09 → 10 → 11：01B 和子系统生命周期设计可以先行，真实设备的
解绑/重绑验收必须等待本票完成，不以 mock 或只退出软件读者代替硬件证据。

### 11：真实 hwrng 纵向接入

覆盖 P7、R03/R05/R06/R09/R10/R11。实际新模型、host、库、class 和 entropy 串成一条。

- 移除旧 RNG 注册后仍被发现；旧注册前分流，同一设备只有一个生命周期管理者。
- 阻塞 read 在退出时被唤醒；实际解绑、重绑、注销均完成资源/发布清理。
- 消费端能区分取消与有效熵；新发布可用、旧句柄不能开始新操作。
- 保留已有节点/事件语义和非 RNG 设备路径，不以 attach_legacy 或全 mock 验收。

### 12：整体验收

覆盖 R01—R13，尤其 R07/R11/R12。此前各票已各自测试，本票检查组合后的交互。

- 至少两个真实 hwrng 实例：退出一个另一个继续；反复解绑/重绑不积累已结束资源。
- 汇总确定性失败/竞争测试与实际 QEMU 证据，不用 mock 替代真实主链路。
- 盘点迁移前已有节点/事件并比较；执行受影响的未迁移 VirtIO 路径回归。
- 对照架构边界 review 依赖、字段权威来源、文档和遗留兼容接口；不把测试通过
  等同于架构合格，不顺带删除仍有旧用户的契约。
