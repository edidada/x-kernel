# timer-driver 安全与可靠性分析

## 信任模型

CPU 频率叶、hypervisor 叶、固件定时器描述、传统定时器行为和平台静态频率都属于
外部输入。驱动在使用发现到的频率建立单调时间前完成数值校验。

## 外部边界

- Intel CPUID leaf `0x15` 和 `0x16` 提供架构频率元数据。
- CPUID leaf `0x40000010` 只在 KVM 和 ACRN hypervisor 标识下提供频率元数据。
- x86 PIT 端口 `0x42`、`0x43` 和 `0x61` 提供校准参考。
- 架构定时器寄存器和 SBI 调用提供计数器及时钟事件。
- 平台配置提供最终 x86 回退频率。
- LAPIC、MMIO、PIO 和架构计数器操作跨越原始硬件接口，要求相关启动阶段先建立访问条件。

## unsafe 代码清单

`src/x86_lapic_tsc.rs::read_tsc_raw` 调用 x86_64 `_rdtsc` intrinsic。该模块只在
x86_64 目标中编译，此指令属于支持架构的基线能力。所有 TSC 读取都经过该私有辅助函数。

`src/x86_lapic_tsc.rs::PitChannel2::{acquire,start_one_shot,has_elapsed}` 及其
`Drop` 实现封装端口 I/O。安全性依赖 CPL0 执行环境，以及在次级处理器和设备驱动启动前
独占 channel 2。`platforms/kplat-x86_64/src/init.rs::BootHandler::early_driver_init`
建立这一启动阶段调用顺序。每次完整采样期间保持本地中断关闭，guard 在释放时恢复捕获的
端口 `0x61` 状态。

`src/x86_lapic_tsc.rs::{init_primary,init_secondary,arm_timer,disarm_timer}` 调用
`x86_apic::with_local_apic`。安全性依赖当前 CPU 已完成 APIC 初始化，并依赖该辅助函数
对可变 LAPIC 寄存器访问进行串行化。

ARM 和 RISC-V 后端在对应源文件中保留架构相关的寄存器与 SBI 不变量。

## 不变量

- TSC 频率至少为 1 MHz，且 kHz 表示可以放入 `u32`。
- 运行时换算比例在单调时间读取开始前只初始化一次。
- QEMU TCG 优先使用 PIT 实测值，高于枚举值和静态值的选择优先级。
- hypervisor timing leaf `0x40000010` 只对 KVM 和 ACRN 解释。
- 架构 CPUID timing leaf `0x15` 和 `0x16` 只对 Intel CPU 解释，leaf `0x16` 与
  leaf `0x15` 的比例共同计算。
- 物理机 PIT 采样至少包含 1000 次轮询，具有非零的相邻 TSC 间隔，并且最大间隔
  不超过最小间隔的十倍。QEMU TCG 采样在 PIT 到期前至少完成一次轮询并产生非零
  TSC 进度，同时允许设备模拟和宿主调度导致更少的轮询及更大的相邻间隔比例。
- PIT 轮询通过 channel 完成、TSC 截止时间或迭代次数上限结束。
- 引导处理器在每次采样期间独占 PIT channel 2。
- LAPIC 定时器编程发生在本地 APIC 初始化完成之后。

## 威胁分析

| 编号 | 威胁 | 影响 | 触发条件 | 现有控制 |
|------|------|------|----------|----------|
| T-01 | 枚举到的 TSC 频率错误 | 中 | CPU 模型或 hypervisor 报告的数值与当前 TSC 速率不一致 | 拒绝零值和超范围值。QEMU TCG 优先使用 PIT 测量值。hypervisor leaf `0x40000010` 只接受 KVM 和 ACRN。 |
| T-02 | PIT 缺失或卡死 | 中 | 传统 channel 2 不存在，或无法到达终端计数 | 轮询同时具备 TSC 和迭代次数上限，失败后继续使用 CPUID 或平台回退值。 |
| T-03 | PIT channel 2 被并发重编程 | 中 | 其他 CPU 或驱动在引导校准期间访问 channel 2 | 校准在次级处理器和驱动初始化前由引导处理器执行，并在采样期间关闭本地中断。 |
| T-04 | 恶意频率导致算术溢出 | 中 | 外部元数据提供极端计数器速率 | 将 kHz 值限制在 `u32` 范围；换算初始化执行范围校验，PIT 算术使用 `u128`。 |
| T-05 | TSC 非 invariant 或 CPU 间未同步 | 中 | 硬件改变 TSC 速率，或各 CPU 暴露未同步计数器 | 当前设计依赖平台提供的 x86 TSC 契约。残余漂移和跨 CPU 偏差属于已接受限制。 |
| T-06 | PIT 轮询延迟使采样膨胀 | 中 | SMI、宿主调度或设备模拟延迟干扰校准 | 物理机丢弃轮询次数过少或相邻间隔比例过大的采样。QEMU TCG 保留轮询进度检查，并从三次完整样本中选择最低值。 |

## 失效模式

| 编号 | 失效模式 | 局部影响 | 系统影响 | 严重度 | 处理方式 |
|------|----------|----------|----------|--------|----------|
| F-01 | 所有运行时频率来源失败 | 选择静态频率 | 单调时间精度依赖平台配置 | 2 | 启动日志记录静态回退来源。 |
| F-02 | PIT 采样延迟 | 实测频率膨胀 | 定时器期限运行变慢 | 3 | 物理机使用轮询次数和相邻间隔检查；QEMU TCG 使用轮询进度检查，并从三次样本中选择最低值。 |
| F-03 | PIT 输出立即为高电平或采样为空 | 无法计算频率 | 丢弃该次采样 | 3 | 继续尝试剩余采样以及其他回退来源。 |
| F-04 | 频率无法放入换算表示 | 初始化断言失败 | 在发布无效时间前停止启动 | 2 | 在初始化换算比例前执行显式范围检查。 |
| F-05 | LAPIC 速率与配置策略不一致 | 时钟事件 IRQ 提前或延后到达 | 期限仲裁可能重复或停滞 | 2 | 现有期限重新仲裁处理提前到达的中断；LAPIC 速率发现仍属于平台常量。 |

## 失效处理

频率发现按顺序降级，并始终保留经 `early_init` 接受的平台静态回退值。无效 PIT
采样返回 `None`。编程错误和不支持的启动顺序保留为断言或 panic，因为发布无效的
单调时钟会破坏整个系统的超时语义。

## 隐私分析

定时器驱动只处理计数器数值和硬件元数据，不处理用户载荷或持久化个人数据。

## 已知限制

- 驱动依赖初始化后可用且全系统一致的 x86 TSC。
- 当运行时枚举缺失或检测到 QEMU TCG 时，PIT 校准依赖 PC 兼容的 channel 2。
- KVM 和 ACRN timing leaf 在完成标识和数值校验后受到信任。
- x86 LAPIC 定时器速率仍是平台常量。

## 审计清单

- 确认新的频率来源在构造换算比例前完成校验。
- 确认厂商专用 hypervisor 叶始终由明确支持的标识限制。
- 确认 CPUID 基频只在 Intel 且 leaf `0x15` 比例有效时使用。
- 确认 PIT 的每条返回路径都恢复端口 `0x61` 状态。
- 确认 PIT 校准仅限引导阶段，且不会与其他所有者竞争。
- 确认 PIT 采样保留轮询进度检查，且相邻间隔比例放宽仅适用于 QEMU TCG。
- 确认轮询保留独立的迭代次数和时间上限。
- 确认公共定时器函数记录启动阶段和 CPU 本地状态前置条件。
